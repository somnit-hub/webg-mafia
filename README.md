# Enjoy Mafia

Мобільний local-first помічник ведучого спортивної «Мафії» на 10 гравців, створений для спільноти кав’ярні **Enjoy**. Основна адреса PWA — [mafia-cafe.web.app](https://mafia-cafe.web.app), а каталог користувачів, активні й завершені ігри та спільна статистика синхронізуються через Cloud Firestore.

## Замовлення напоїв у Telegram

Робоче меню збережено в Google Sheets: [Меню Mafia Enjoy](https://docs.google.com/spreadsheets/d/1_hz7mJ_H40c22bLjkyNHJvSSmHnkrGnNO44IMODgubE/edit). Аркуш `menu_items` містить напої, переклади, ціну, об’єм, іконку, доступність та порядок; аркуш `options` — розміри, молоко, цукор та інші додатки до конкретних позицій. Для читання меню Worker-ом установіть для таблиці доступ **Усі, хто має посилання → Читач**. Зміни з’являються у застосунку протягом п’яти хвилин; якщо таблиця тимчасово недоступна, працює вбудоване резервне меню. Тестовим одержувачем замовлень налаштовано `@Chemelev`.

Telegram не дозволяє боту автоматично написати приватному користувачеві лише за його `@username`: користувач спочатку має відкрити створеного бота й натиснути **Start**, після чого застосунку потрібен числовий chat ID. Налаштування виконується так:

1. Створіть бота через `@BotFather`.
2. Локально вставте отриманий токен після `TELEGRAM_BOT_TOKEN=` у проігнорований Git файл `functions/.secret.local`. Не надсилайте токен у чат і не додавайте його до commit.
3. Відкрийте бота з акаунта `@Chemelev` і натисніть **Start**.
4. Встановіть залежності й отримайте chat ID:

```powershell
cd functions
npm install
npm run telegram:chat-id
```

5. Скопіюйте надрукований рядок `ORDER_TELEGRAM_CHAT_ID=...` у `functions/.secret.local`.
6. Для production опублікуйте Cloudflare Worker, передавши локальний файл секретів без додавання його до Git:

```powershell
npx --yes wrangler@4 deploy --config cloudflare/wrangler.jsonc --secrets-file functions/.secret.local
```

Worker працює окремо від Firebase Hosting і Firestore, тому для замовлень не потрібен тариф Firebase Blaze. Сам токен ніколи не потрапляє в браузер: Worker перевіряє Firebase-сесію через офіційний Auth REST API, приймає лише доступні позиції з таблиці та обмежує частоту замовлень через Durable Object. `functions/.env.local` містить несекретні ідентифікатори Google/Firebase та тестовий Telegram-нік, а `functions/.secret.local` — приватні значення; обидва файли виключені з Git, Firebase Hosting і GitHub Pages. Production endpoint: `https://enjoy-mafia-orders.webg-mafia.workers.dev/orders`, публічне меню: `https://enjoy-mafia-orders.webg-mafia.workers.dev/menu`.

Цей самий Worker обслуговує анонімні оцінки завершених ігор за адресою `/ratings`. Перед записом він перевіряє Google-сесію та наявність профілю користувача серед учасників гри. Окремий голос зберігається у Durable Object під SHA-256-ключем без email або імені; застосунок отримує власний вибір і лише агреговане зведення. Щоб ведучий не міг визначити першого автора, зведення відкривається після трьох оцінок.

## Публікація

Основний production-хостинг — [mafia-cafe.web.app](https://mafia-cafe.web.app). Сторінка та службовий обробник Google-входу працюють на одному домені, що також усуває проблему redirect-входу в Safari на iPhone.

```powershell
npx --yes firebase-tools@15.26.0 deploy --only hosting:mafia,auth
```

GitHub Pages залишається резервною статичною публікацією. У репозиторії є workflow [pages.yml](./.github/workflows/pages.yml). Після першого push:

1. Відкрийте **Settings → Pages**.
2. У **Build and deployment → Source** виберіть **GitHub Actions**.
3. Push у `main` опублікує статичний застосунок.

Усі URL у проєкті відносні, тому він працює і за адресою виду `https://USER.github.io/REPOSITORY/`.

## Google-only вхід

Production-збірка вже підключена до Firebase-проєкту `somnit-mafia-desk`: Google-провайдер увімкнений, `mafia-cafe.web.app` використовується як основний домен входу, а `somnit-hub.github.io` збережений як резервний дозволений домен. Користувачі не вводять OAuth Client ID — стартовий екран показує лише кнопку **Увійти через Google**.

Конфігурація провайдера зберігається у [firebase.json](./firebase.json) і повторно застосовується командою:

```powershell
npx --yes firebase-tools@15.26.0 deploy --only hosting:mafia,auth,firestore:rules
```

Для перенесення на інший Firebase-проєкт:

1. Створіть Firebase-проєкт і зареєструйте Web App.
2. У **Authentication → Sign-in method** увімкніть тільки провайдер **Google**.
3. У **Authentication → Settings → Authorized domains** додайте production-домен хостингу, `somnit-hub.github.io` і `localhost` для розробки.
4. Скопіюйте Firebase Web config до [firebase-config.js](./src/firebase-config.js).
5. Не додавайте до репозиторію service-account JSON, private key або `client_secret`.

Firebase Web config та його `apiKey` є публічними ідентифікаторами проєкту, а не секретами. Новий Google-вхід потребує мережі; збережена Firebase-сесія та локальний SDK-кеш дозволяють уже авторизованому ведучому запускати PWA офлайн.

Перший вхід створює профіль із Google-імені та фото у колекції `communities/enjoy/members`. У Mafia можна змінити ім’я для відображення, нікнейм, клуб, опис і видимість у каталозі. Email не записується до спільної колекції, а технічний ідентифікатор використовується лише для зв’язування даних одного облікового запису.

Доступ до Google Drive не запитується під час входу. Ведучий окремо натискає **Увімкнути резервну копію**, після чого Firebase повторно підтверджує той самий Google-акаунт і запитує лише scope `drive.appdata`.

Користувач може видалити власний профіль Mafia у розділі **Ще → Профіль Enjoy**. Видаляються Firebase Authentication-акаунт застосунку, запис у каталозі Enjoy та локальна база цього UID на поточному пристрої. Сам Google-акаунт, окрема резервна копія Google Drive і вже завершені спільні протоколи не видаляються.

Кожен користувач із Google-профілем з’являється у закритому каталозі Enjoy і може бути знайдений ведучим. Гості без Google-реєстрації все одно можуть грати через локальний профіль або тимчасове місце за столом.

Для ручного профілю ведучий може вказати email. У Firestore створюється мінімальне приватне запрошення без нотаток і фото. Прочитати його можуть лише ведучий-власник та користувач із таким самим підтвердженим Google-email. Після згоди гравця локальний ідентифікатор у власних іграх ведучого замінюється на канонічний Google UID, а завершені протоколи повторно синхронізуються. Email не додається до каталогу `members` або публічних протоколів.

## Модель даних і приватність

Застосунок використовує гібридну модель. Cloud Firestore містить профілі каталогу Enjoy і санітизовані протоколи завершених ігор, доступні після Google-входу. Правила `firestore.rules` дозволяють користувачу змінювати власний профіль і лише ті ігри, які він провів. Пошук і статистика обчислюються у браузері за синхронізованими даними, тому окремий сервер не потрібен.

Окрема IndexedDB `mafia-desk-FIREBASE_UID` для кожного ведучого містить приватні й ігрові дані:

| Store | Вміст |
|---|---|
| `players` | постійні профілі та стиснені аватари |
| `games` | локальна робоча копія активних і власних завершених ігор |
| `settings` | профіль ведучого, черга наступної гри, таймери, UX-параметри та час sync |

Склад гравців копіюється в гру на старті. Тому перейменування або видалення профілю не переписує історичний протокол. Після оновлення зі старої версії застосунок пропонує одноразово скопіювати базу `mafia-desk` до бази першого авторизованого профілю; вихідну базу не видаляє.

Для оглядачів синхронізується лише очищений публічний стан активної гри. Ролі, профільні ID, нічні цілі, результати перевірок, приватний протокол і нотатка ведучого залишаються на пристрої ведучого. Після завершення застосунок публікує результат, склад, відкриті ролі та протокол у спільний архів. Власне стиснене фото профілю синхронізується в каталозі та має пріоритет над Google-фото.

На інших пристроях режим оглядача отримує лише очищений live-стан без ролей і нічних рішень. На пристрої ведучого секрети залишаються в локальній базі, тому не надавайте глядачам доступ до його профілю браузера або інструментів розробника.

## Відомі межі та наступні кроки

1. **Турнірні очки.** Правила нарахування додаткових балів різняться між лігами. Варто додати окремі конфігуровані rulesets після затвердження формули конкретного клубу.
2. **Активна гра на кількох пристроях.** Live-стан доступний глядачам на різних пристроях, але повна приватна гра належить одному пристрою ведучого. Для одночасного ведення з кількох телефонів потрібні ревізії стану й окремий механізм блокування сесії.
3. **Фото профілів.** Стиснені квадратні аватари синхронізуються без окремого файлового сховища. Не використовуйте великі зображення як галерею: цей механізм призначений лише для одного компактного фото профілю.
4. **Bluetooth і зовнішні програвачі.** Вебсторінка не може керувати Spotify, YouTube Music чи системним Bluetooth-аудіо. Play/Pause працюють лише з локальним файлом у Mafia; звук використовує вже вибраний телефоном аудіовихід. Web Bluetooth chooser призначений для BLE-пристроїв і доступний не в усіх мобільних браузерах.
5. **Регламент клубу.** Базова state machine покрита тестами для ролей, паритету, голосування, повторної нічиєї, нічних цілей, Кращого ходу та відновлення. Турнірні бали й автоматичний критерій нічиєї варто прив’язувати до редакції регламенту конкретної події.

## Перевірка перед релізом

- запустити повну тестову гру на iPhone Safari та Android Chrome;
- встановити PWA, вимкнути мережу й перезавантажити після першого онлайн-відкриття;
- перевірити OAuth саме з production origin;
- зробити JSON export, очистити тестовий профіль браузера й перевірити import;
- пересвідчитися, що публічний екран не показує ролі, приховані записи та результати нічних перевірок.
